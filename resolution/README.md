# Run declaration resolution

The Rust CLI embeds DuckDB 1.4.4 and executes bundled SQL generated by Splink 4.0.17. Normal builds, tests, and resolution require no Python environment. The frozen model supplies every comparison parameter. Its probabilities are computed but uncalibrated.

Configure the ingestion data directory and candidate budget:

```yaml
data_dir: data
candidate_budget: 1000000
```

`data_dir` is relative to the invocation directory. The budget applies to profile candidates and expanded source-observation pairs. Increase it explicitly when the command refuses a larger candidate set.

Resolve an existing cleaned run:

```sh
cargo run --package exposed --bin exposed -- data declarations resolve exposed/config/declaration-resolution-dev.yaml --ingestion-key UUID
```

The command prints the output path and counts. The bundle contains observation resolutions, payment attributions, candidate decisions, and a manifest. It refuses an existing bundle. Older cleaned schemas require cleaning retained raw capture into a fresh run. Raw files are not needed after the current cleaner has produced the checked pair.

Run the Rust tests with `DATABASE_URL` set to a PostgreSQL database containing the current schema. Existing SQLx macros need that database at compile time. Resolution itself runs offline.

```sh
cargo test --package exposed --lib
cargo test --package exposed --test declaration_resolution_cli
```

The CLI tests run with an empty `PATH`. They clean raw evidence and resolve two charity observations with statistical support and four Gary Lubner donor observations with missing or disagreeing addresses. They check the actual names in each identity, computed scores, and refusal to overwrite the result. They remove raw evidence before resolution to verify that the resolver reads only cleaned inputs. A repeated-observation case verifies budget refusal before publication and succeeds after an explicit budget increase.

## Regenerate the frozen model SQL

The canonical model and settings live in `exposed/resources/funder-resolution/model.json`. The bundle also contains `schema.sql`, `count.sql`, `concat.sql`, `candidates.sql`, `predict.sql`, `output.sql`, and `artifact.json`. Runtime manifests record DuckDB's version, the Splink generator version, the model settings, and the SQL SHA-256 digest.

Only optional developer regeneration requires Python. From the repository root, create an isolated environment and install `resolution/requirements.txt`, which pins `splink==4.0.17` and `duckdb==1.4.4`:

```sh
python3 -m venv /tmp/exposed-resolution-generator
/tmp/exposed-resolution-generator/bin/python -m pip install -r resolution/requirements.txt
/tmp/exposed-resolution-generator/bin/python resolution/generate.py --check
```

`--check` verifies that the generated SQL and reference fixtures match the tracked artifacts. To regenerate them after an intentional model change, run `resolution/generate.py` without `--check` in the same environment.

Policy `funder-resolution-v3` uses cleaner-extracted aliases and organization-name evidence, punctuation-normalized numbered-street addresses, and typed candidate keys for aliases and `Unite` trade unions. HSBC's CEO-annotated bank name can link to its legal bank name when distinctive organization terms and the numbered-street address agree. Regional and branch spellings with an explicit `Trade Union` kind and the `Unite` root can resolve to one funder identity. Person/organization conflicts and competing company numbers still block merges; ambiguous fuzzy names stay review candidates. Each named singleton receives a separate provisional run-local identity. See the [resolution policy](../docs/funder-resolution-design.md) for attribution and repeat behavior.
